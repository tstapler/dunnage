# CLAUDE.md

This file guides Claude Code when working in this repository. It was generated by the `code-new-project` skill's library/CLI/MCP-tool path — see that skill's `reference.md` for the rationale, modeled on `tstapler/kibitzer`.

## Stack

- Layout: multi-crate
- CLI: `clap` derive, flat flags (`-n`/`--dry-run`, `-v`/`--verbose`, `--stale-days`) — no subcommands
- MCP: not used. This tool has no need for an MCP surface, so the scaffold's `rmcp`/`tokio`/`Mcp` subcommand were removed rather than left as dead code.
- Release: `cargo-dist` (`dist-workspace.toml`) triggered by a human-pushed version tag, changelog via `git-cliff` (`cliff.toml`) — see `RELEASE.md`
- CI: GitHub Actions — `.github/workflows/ci.yml` gates PRs (fmt/clippy/test), `.github/workflows/release.yml` (generated by `dist generate`, do not hand-edit) runs on tags
- Pre-commit: Lefthook (`lefthook.yml`) — run `lefthook install` after cloning

## Development Workflow

**Planning and implementing features**: use `/sdd:full` (or the individual phases) for anything non-trivial; `/sdd:quick` for small fixes.

**Cutting a release**: see `RELEASE.md` — do not push a tag from a bot-authored commit (release-please-style), and do not hand-edit `.github/workflows/release.yml` (regenerate via `dist generate` instead).

## Architecture Notes

- Keep transport code (CLI arg parsing, MCP tool handlers) thin; put real logic where it's independently testable (see `crates/core/`).
- `cargo-dist`'s config (`dist-workspace.toml`) and its generated workflow can drift from each other if one is edited without the other — always regenerate via `dist generate` after changing the config.

## Accepted kibitzer Findings

`syntax-rules-rust`'s `flag-argument` rule fires on three genuine hits in
`crates/cli/src/main.rs` that are intentionally left as-is rather than
suppressed (kibitzer has no per-rule-id suppression — only whole-checker
disable/rescope via `.claude/inspect.json`, which would also silence
`long-function`/`deep-nesting`/etc. for this file):

- `Mode::from_dry_run_flag`: the single boundary adapter turning the clap
  `bool` into `Mode`. Something has to do that conversion once; splitting it
  further just moves the branch, it doesn't remove it.
- `verbose: bool` on `cleanup_worktrees`/`cleanup_worktrees_in_repo`/
  `handle_worktree_candidate`: a reporting-verbosity toggle, the standard
  exception to Fowler's *Remove Flag Argument* — every CLI's `-v` works this
  way, and splitting into verbose/quiet twin functions would be ceremony
  with no behavior difference.

If a future edit adds a *new* flag-argument finding in this file, evaluate it
on its own; don't assume it's covered by this note.
