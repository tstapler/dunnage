# CLAUDE.md

This file guides Claude Code when working in this repository. It was generated by the `code-new-project` skill's library/CLI/MCP-tool path — see that skill's `reference.md` for the rationale, modeled on `tstapler/kibitzer`.

## Stack

- Layout: multi-crate
- CLI: `clap` derive in `crates/cli/src/args.rs`. Dry run is the default and `--apply` deletes; `-n`/`--dry-run` are accepted no-ops that conflict with `--apply` (exit 64); `--plan-id` gates destructive kinds; subcommands `status`, `kinds`, `steam` and `audit verify`. Exit codes 0/1/2/3/64/74/130/143 (`--help` lists them); usage errors are remapped from clap's 2 to 64. `main.rs` only wires the real ports; `app::run` takes them as `Ports`, so every acceptance criterion runs against fakes.
- MCP: not used. This tool has no need for an MCP surface, so the scaffold's `rmcp`/`tokio`/`Mcp` subcommand were removed rather than left as dead code.
- Build, test, lint: Bazel (`scripts/bazel.sh`, `MODULE.bazel`; ADR-008); Cargo manifests remain the dependency source of truth (`cargo build|test|clippy` still work; `scripts/check-bazel-cargo-sync.sh` fails on drift)
- Release: Bazel archives (`--config=dist`) triggered by a human-pushed version tag, changelog via `git-cliff` (`cliff.toml`) — see `RELEASE.md`
- CI: GitHub Actions — `.github/workflows/ci.yml` gates PRs (Bazel build/lint/test on three runners), `.github/workflows/release.yml` (thin caller of gha-actions' `rust-bazel-release.yml`) runs on tags
- Pre-commit: Lefthook (`lefthook.yml`) — run `lefthook install` after cloning

## Development Workflow

**Planning and implementing features**: use `/sdd:full` (or the individual phases) for anything non-trivial; `/sdd:quick` for small fixes.

**Cutting a release**: see `RELEASE.md` — do not push a tag from a bot-authored commit (release-please-style), and keep `.github/workflows/release.yml` a thin caller (the logic lives in tstapler/gha-actions).

## Architecture Notes

- Keep transport code (CLI arg parsing, MCP tool handlers) thin; put real logic where it's independently testable (see `crates/core/`).
- Bazel's `BUILD.bazel` files and the Cargo manifests can drift (a new binary, example, `[[test]]` or Cargo feature has no Bazel target until someone adds one): run `scripts/check-bazel-cargo-sync.sh`; after a dependency change repin with `CARGO_BAZEL_REPIN=1 scripts/bazel.sh query @crates//:all`.

## Accepted kibitzer Findings

`syntax-rules-rust` flags a few long functions in `crates/cli/src/app.rs` (`apply_mode`, `plan_mode`): each is one
linear sequence of the ordered steps of `design/ux.md` 1.4 and splitting it would scatter that order. A new finding
in this file is evaluated on its own; this note does not cover it.

`progress_mode` takes five `bool`s on purpose: they are the inputs of the UX-59 truth table, and its tests iterate all
32 combinations. `Cli` is a set of independent switches, so clippy's `struct_excessive_bools` is allowed on it.
